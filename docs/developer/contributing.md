# Contributing

The repository's `CONTRIBUTING.md` has the short version; this page adds the
conventions behind it.

## Workflow

1. Branch from the development branch: `fix/<topic>` or `feat/<topic>`.
2. Keep a change to one topic, with tests.
3. Run the [tests](testing.md) that cover it: always the web app suite for
   Python changes, a rendering comparison for configuration changes, the
   system tests for cluster changes.
4. Describe in the pull request what changes for administrators and users, and
   how you tested it, including what you could not test.

Security problems are reported privately (`SECURITY.md`), not in issues.

## Conventions

**General**

- Match the style of the surrounding code, including its comment density.
  Comments explain *why*, not *what*.
- No new dependencies without need. The web app's dependencies are pinned in
  `requirements.txt`; downloaded tools are pinned to a tag and verified
  against a commit or checksum (`install.sh`).
- User-visible names: "Crassostrea" for the product; technical names keep the
  `spamfilter` prefix (units, paths, the Python package).

**Shell scripts**

- `bash`, `set -o pipefail`, helpers from `system/lib/common.sh` (`log`,
  `warn`, `die`, `write_file`, `create_file`, `run`, `p`, `dry`).
- Every file written goes through `p()`/`write_file` so it lands below
  `$SF_ROOT`; every command that changes the system goes through `run` or is
  skipped with `dry`. Otherwise dry-run rendering and the tests break.
- Never source `spamfilter.conf`; use `load_env_file`/`load_config`.
- New executable files need their execute bit in git.
- Configuration files that administrators may edit are created once
  (`create_file`); generated files carry a "Generated by ... - do not edit"
  header.

**Web app**

- Business rules belong in `services/`; views and API routes parse input, call
  the service, commit, and call `sync_all()` when filter configuration changed.
  Raise `ServiceError` with a field name and status.
- Every API route is documented in `api/spec.py`.
- Pages must work without JavaScript. New live content goes into a partial
  rendered through `render_live`; in-place forms (`data-async`) must redirect
  back to the page of their region.
- Templates escape everything; quarantined HTML is never rendered.
- Settings for Rspamd that depend on recipients use the selectors in
  `rspamd.local.lua`, never a plain `rcpt` condition for allow rules or
  thresholds (see [Design decisions](design.md#per-recipient-rules-in-a-per-message-filter)).
- Anything the web app cannot do as `spamfilter` is a request file and a root
  service that validates it again, never `sudo` or a writable root-owned file
  (see [Root services](design.md#root-services-for-the-web-ui)).
- New global settings get a default in `models.SETTING_DEFAULTS`, a group in
  `filters.py` (and `ALL_SETTINGS`), validation in `update_settings`, and a
  property in the API spec's settings schema. Secrets go into
  `SECRET_SETTINGS` (write-only) and never into map files.
- Views of blueprints that admit domain administrators limit every query to
  `scope()` and check single objects with `require_scope()`.
- New tables need nothing for `init-db` (`create_all`); new columns of
  existing tables need an entry in `cli._MIGRATIONS`.

**Rspamd checks**

- A check whose verdict must not depend on the spam score (reject, defer) is
  a prefilter; read the direction from `relay_networks` or the symbols
  `SF_MAIL_DIRECTION` sets, never from multimap symbols that a high score can
  skip.
- Configuration comes from maps written by `maps.build_rspamd_maps()`; Valkey
  scripts live in their own `*.redis.lua` file with a test in fakeredis;
  detectors that also exist in Python keep a parity test.
- Fail open: when Valkey or a lookup does not answer, mail passes (and is
  logged), it is never held up.

**Cluster code**

- A single gateway (empty `HA_NODES`) must render exactly as before.
- Never restart a member's database, Valkey or Sentinel unconditionally; use
  `restart_if_changed`.
- Anything that must happen once per cluster takes a job lock.

## Commit messages

A short summary line in the imperative ("Add DKIM rotation to the API"),
a blank line, then what changed and why, wrapped at 72 characters. Mention
behaviour changes for existing installations explicitly.
